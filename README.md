# 電池數據分析：三個算得出來、但不能直接用的數字

*Battery data analysis — three numbers that compute cleanly and still can't be used as-is.*

這個 repo 是一份分析報告的可執行部分。報告本身在 [`docs/`](docs/)。

報告要證明的一句話是：**一個數字只屬於產生它的那一整套東西。**
所以這個 repo 存在的理由，是讓你自己跑一次、自己看那三個數字會不會回來。

---

## 三個數字

| | 數字 | 它屬於什麼 | 目錄 |
|---|---|---|---|
| **資料分析** | **0.0043 Ah** | 這個分析方法 ＋ 這批資料本身 | [`aging/`](aging/) |
| **參數驗證** | **1247 秒** | 這顆電池 ＋ 這台環境室 ＋ 這條假設路徑 | [`thermal/`](thermal/) |
| **電芯模擬** | **33.6 倍** | 這個負載設定 ＋ 這三組參數 ＋ 各自的終止條件 | [`cell/`](cell/) |

- **0.0043 Ah** — 用 A/A Testing（拿兩組本來就該相同的資料相減）量到的統計底噪。
  它是想找的那個趨勢訊號（0.0014 Ah）的 **3 倍**，所以那個訊號不成立。
- **1247 秒** — 兩條假設量不同的獨立物理路徑，對同一個散熱時間常數 τ 給出 841 s 與 2088 s。
  容差 ±186 s 在看到第二條路徑的結果**之前**就凍結了。落差是容差的 6.7 倍，相容性檢定不通過。
- **33.6 倍** — 同一個模型、同一組 7.5C 負載，只換 PyBaMM 內建參數集，
  四組跑出四種結局，有解的三組之間最大溫升差 33.6 倍。

## 怎麼跑

```bash
pip install -r requirements.txt
```

### aging（資料分析）

```bash
cd aging
python clean_s2_data.py                 # 四個原始檔 → Master Table
python analyze_capacity.py              # 衰退率、趨勢訊號、A/A Testing 底噪
```

輸出到 `aging/output/`。預期會印出：

```
線性衰退率：-0.05869783648002918 Ah/cycle
表面趨勢差距 (訊號)：0.0014285714285782736 Ah
統計底噪 (雜訊)：0.0042857142857185004 Ah
底噪為表面訊號的 2.999999999988576 倍
```

> 最後那個數在數學上精確等於 3（訊號 ≈ 1/700、底噪 ≈ 3/700），
> 印出來的 `2.99999...` 是浮點表示。
> **不同平台的 `np.polyfit` 可能讓衰退率在末幾位不同**，這在實測中發生過。

### cell（電芯模擬）

```bash
cd cell
python W5_process.py                    # 四組 PyBaMM 參數集，同一組 7.5C 負載
python make_w5_fig.py                   # 出圖
```

輸出到 `cell/output/`，其中 `environment.json` 記錄執行當下的套件版本。

### thermal（參數驗證）

先取得 NASA 資料集（見下），然後：

```bash
cd thermal
python W2b_process.py --data-dir <cleaned_dataset 的路徑>
python W2c_process.py --data-dir <同上> --w2b-dir output
```

## 資料來源

### `aging/data/` — LFP280 測試集（含在 repo 內）

> ⚠️ **這是為了演練資料結構化流程而設計的合成資料集，不是實測資料。**
> 它內含**預先埋設的資料品質缺陷**（不一致的日期格式、mAh/Ah 混用、欄位缺漏），
> 用來取得一組真值已知為零的對照。
> **請不要把它當成真實電池的老化資料使用。**

4 檔、172 圈。老化分析只用其中 A1 那一檔的 42 圈（0.33C）。

### `thermal/` — NASA Ames PCoE Battery Data Set（不含在 repo 內）

使用 B0005、24 °C、2 A 放電，166 個通過品質閘的循環。

> ⚠️ **本專案使用的是經第三方清洗轉換過的 `cleaned_dataset/` 格式，不是原始 `.mat`。**
> 原始下載來源目前**待確認**——專案紀錄未留下確切網址。
> 這一點沒有補一個看起來合理的連結上去。

### `cell/` — PyBaMM 內建參數集（不需下載）

`Marquis2019` / `Chen2020` / `Ecker2015` / `Prada2013`，由 PyBaMM 套件本身提供。

## 執行環境

最後一次完整驗證的環境：

```
Python  3.13.14
numpy   2.4.6
scipy   1.18.1
pandas  3.0.5
pybamm  26.8.0.0
```

`cell/` 的結果與 2026-08-25 的產出**逐字節相同**，是在上述 `pybamm 26.8.0.0` 下驗證的。

> PyBaMM 的內建參數集屬於特定版本的 PyBaMM。
> 換一個版本會不會得到不同的數字，**本專案沒有測過，因此不作任何宣稱。**
> `requirements.txt` 釘死版本，是為了讓別人拿到的是同一套東西。

## 這裡沒有放什麼

- **`*/output/`**：腳本的產物不進版控（`cell/output/environment.json` 除外，那是環境證據）。
  這個 repo 的價值在於「跑一次就能自己產生」，不在於附上答案。
- **迭代過程中的二十幾支腳本**：`W1b`–`W1g`、`W2pre` 系列、`W3` 系列等。
  裡面最值得看的那一段，寫在 [`docs/iteration-log.md`](docs/iteration-log.md)——
  **第一版的路徑 B 通過了相容性檢定，而它是壞的。**
